# UX / Product Design Evidence Workflow

This ten-stage design evidence workflow is distinct from (a) the seven interactive product-planning checklist phases in the dashboard and (b) the seven CSV-processing phases and five runtime data agents. Its local executable is `orchestration/ux-workflow.js`; it checks artifact presence and writes a manifest. It does not perform AI research, access external sources, conduct interviews, or claim usability execution.

| # / stage | Agent/role and skill | Inputs | Execution method | Outputs | Gate / approval | Downstream |
|---|---|---|---|---|---|---|
| 1. Problem Definition and Product Brief | Product brief compiler; requirements synthesis | BRD, approved decisions | Manual/source-based synthesis; UX audit verifies provenance labels | `artifacts/00-problem-definition/*` | Business owner approves scope/schema/targets | Research planning |
| 2. Research Planning and Evidence Collection Plan | Research planner; research planning | BRD hypotheses, open decisions | Create participant and source research plan; no interviews are run | `artifacts/01-research/research-plan.md` | Owner approves recruitment, consent, handling | Evidence collection |
| 3. Desk Research and Competitor Evidence | Evidence registrar; desk research | Approved source access and plan | Future stage requires cited source title/URL/access date; current artifacts state not performed | `artifacts/01-research/desk-research.md`, `competitor-analysis.md`, `evidence-register.md` | Researcher review of relevance and factual claims | Personas and JTBD |
| 4. Personas and Jobs to Be Done | Discovery synthesizer; persona/JTBD synthesis | BRD and future participant evidence | Current docs are explicitly BRD-derived candidate hypotheses | `artifacts/02-discovery/personas.md`, `jobs-to-be-done.md` | Validate with actual users before treating as representative | Journeys |
| 5. User Journeys and Task Flows | Journey mapper; task-flow modeling | Requirements, validated needs, risk gates | Document current/candidate task path and approval points | `artifacts/02-discovery/user-journeys.md`, `task-flows.md` | Data steward validates policy decision points | IA |
| 6. Information Architecture | IA designer; information architecture | Journey, application inventory | Map the dashboard, local cleaner, and evidence library | `artifacts/03-design/information-architecture.md` | Product owner confirms page separation | Interaction design |
| 7. Interaction Design and Design System | Interaction designer; interaction specification/accessibility | IA, existing HTML/CSS | Source inspection and decision log; no formal WCAG audit is claimed | `artifacts/03-design/design-decisions.md`, `interaction-specification.md`, `design-system.md`, `accessibility-review.md` | UX and accessibility review required | Prototype implementation |
| 8. Prototype / Application Implementation | Frontend and orchestration engineer; implementation | Approved requirements, existing app, deterministic core | Executed code changes, tests, and CLI demonstration | `artifacts/04-implementation/*`, app source, `runs/<id>/` | Code review, acceptance tests, import remains blocked | Usability/QA |
| 9. Usability Test Planning, QA, and Iteration | QA/research evaluator; usability plan and test skills | Working app, synthetic fixture, criteria | Automated tests run; participant study planned only | `artifacts/05-evaluation/*` | Human review of observed failures and real participant consent/results | Final evidence review |
| 10. Final Product and Evidence Review | Evidence auditor; certification evidence indexing | Source files, run outputs, test reports | `npm run ux:audit` verifies artifact existence; human inspects claims and limitations | `artifacts/06-final/*`, traceability matrix | Reviewer verifies provenance and separates unexecuted stages | Handover |

The UX audit currently marks present stage materials `DOCUMENTED_DRAFT`, not `PASSED`. Product/design choices needing approval remain in `workflow/REQUIREMENTS.md` and the canonical schema proposal.
