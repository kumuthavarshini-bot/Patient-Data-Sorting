# Candidate user journey

1. Select and inspect a CSV; receive actionable file errors.
2. Review headers, missingness, and potential duplicate identifiers.
3. Confirm source-to-canonical mappings; resolve ambiguity.
4. Review proposed transformations and preserved originals.
5. Inspect record and dataset validation outcomes.
6. Correct exceptions and run validation again.
7. Preview eligible records, confirm import when a destination is configured, then review receipt.

Journey is BRD-derived and not usability-tested. The current application has no real import destination.
